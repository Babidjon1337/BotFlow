# E2E release checklist (user-facing part)

Запускать в тестовом контуре с отдельными Telegram-ботами и тестовой YooKassa.
Не использовать production токены в локальном `.env`.

## Подготовка

- `alembic upgrade head` завершён без ошибок.
- Backend доступен по HTTPS, `WEBHOOK_URL` указывает на актуальный туннель/домен.
- У каждого тестового бота webhook установлен на `/webhook/bots/{id}`.
- В `.env` есть SaaS YooKassa test `shop_id`/secret и `SAAS_YOOKASSA_VAT_CODE=1`.

## Создание и запуск

1. Открыть Mini App из главного бота, создать клиентского бота с валидным токеном.
2. Нажать `/start` владельцем в созданном боте.
3. Убедиться, что Mini App перестал показывать состояние «нужна синхронизация» после перезагрузки.
4. Заполнить все обязательные поля воронки, сохранить и запустить бот.
5. Удалить обязательное поле, сохранить: бот должен перейти в draft и сообщить причину.

## Медиа и токен

1. Загрузить фото, видео и документ в старт/дожим; preview доступен для фото и видео.
2. Получить `/start` лидом: Telegram отправляет нужный тип медиа.
3. Сменить токен: бот становится draft, media исчезает из схемы, требуется `/start` владельца и повторная загрузка.

## Продажи

1. В `auto` проверить один и несколько тарифов: один счёт на выбранный тариф, сумма и описание совпадают.
2. В `application` касса не требуется; нажатие открывает публичный Telegram-чат менеджера и предзаполняет текст. Проверьте отправку лида после нажатия им «Отправить».
3. В `hybrid` доступны две кнопки: оплата и переход в чат менеджера с тем же предзаполненным текстом. Проверьте обе ветки, включая дожимы.
4. Завершить test payment YooKassa. Webhook должен единожды выдать выбранный тариф и отразить успешную оплату в статистике.
5. При вводе email в checkout YooKassa получает `receipt.customer.email` и отправляет чек своим механизмом.
6. Для магазина с подключённым «Плати частями» включить опцию в настройках бота и проверить тариф на 1 000–50 000 ₽. В созданном платеже YooKassa должен быть payment method `sber_bnpl`; для другой суммы показать понятную ошибку формирования счёта.

## PRO

1. Купить лицензию, затем PRO; после PRO создать дополнительные боты.
2. Смоделировать три неудачных продления: обязательные уведомления приходят в главный бот, PRO снимается, остаются только лицензированные боты и один активный.
3. Успешное автопродление присылает обязательное подтверждение списания.

## Финальный gate

- `backend/venv/Scripts/python.exe -m pytest -q` — успешно.
- `frontend/npm run build` — успешно.
- `npm run lint` — не должен иметь errors до production release.
- Проверить логи backend: нет 5xx для webhook Telegram/YooKassa.
