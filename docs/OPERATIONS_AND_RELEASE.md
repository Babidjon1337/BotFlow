# BotFlow — эксплуатация и выпуск
Статус: рабочая памятка без секретов.

## 1. Домены

| Переменная | Домен | Назначение |
|---|---|---|
| `WEBHOOK_URL` | `https://botflow.malinaezo.ru` | Mini App, API и callbacks платёжных систем |
| `TG_WEBHOOK_URL` | `https://tg-botflow.malinaezo.ru` | webhooks главного и клиентских Telegram-ботов |

Telegram webhook не должен устанавливаться на `WEBHOOK_URL`. Платёжные callbacks не должны устанавливаться на `TG_WEBHOOK_URL`.

## 2. Сервисы production

- FastAPI/Uvicorn: `127.0.0.1:8001`;
- Nginx раздаёт frontend build и проксирует API/webhooks;
- systemd unit: `botflow.service`;
- база: PostgreSQL;
- миграции: Alembic.

## 3. Безопасное обновление

```bash
cd /var/www/BotFlow
git pull origin main

cd /var/www/BotFlow/backend
source venv/bin/activate
pip install -r requirements.txt
alembic upgrade head

cd /var/www/BotFlow/frontend
npm ci
npm run build

sudo nginx -t
sudo systemctl reload nginx
sudo systemctl restart botflow
sudo systemctl status botflow --no-pager
```

Перед production-деплоем проверяется diff миграций и наличие резервной копии БД. `alembic revision --autogenerate` не выполняется на production как часть обычного deploy.

## 4. Диагностика

```bash
journalctl -u botflow.service -f
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log
sudo nginx -t
sudo certbot renew --dry-run
```

Проверка endpoint через `GET` или `HEAD` может возвращать `405 Method Not Allowed`; это нормально для POST-only webhook, если TLS и маршрутизация работают.

## 5. Автоматические проверки

Локальные команды выполняются из соответствующей директории:

```powershell
backend\venv\Scripts\python.exe -m pytest -q
cd frontend
npm run lint
npm run build
```

Перед релизом все ошибки lint/build/pytest должны быть либо исправлены, либо явно задокументированы как известный блокер. Предупреждение не считается автоматически безопасным.

## 6. E2E: аккаунт и бот

1. Новый пользователь видит Welcome без workspace-навигации.
2. Создаёт бесплатный черновик воронки продаж.
3. Возвращается в приложение и попадает в последний Bot Workspace.
4. Переключает бота без потери несохранённых изменений.
5. Удаляет тестовый черновик с понятным подтверждением.

## 7. E2E: сценарий и медиа

1. Старт и предложения проходят readiness-проверку.
2. Дожимы можно удалить до нуля и добавить до пяти.
3. Фото и видео загружаются, заменяются, удаляются и видны в preview.
4. После замены Telegram-токена старое media не считается готовым.
5. Изменение текста с последующим возвратом к сохранённому значению снимает dirty-state.
6. Публикация с реально нарушенным обязательным полем блокируется сервером.

## 8. E2E: режимы продаж

### Автопродажа

- лид выбирает одно предложение;
- создаётся счёт с правильной суммой;
- оплата приводит к правильной выдаче.

### По заявкам

- бот публикуется без кассы;
- лид может связаться с владельцем;
- владелец отправляет одно или несколько предложений;
- лид выбирает одно и создаёт счёт.

### Гибрид

- доступны автоматическая ветка и связь с владельцем;
- обе ветки сохраняют одного и того же лида внутри данного bot/platform context.

## 9. E2E: платежи и выдача

Проверить отдельно для каждого поддерживаемого провайдера:

1. создание ссылки;
2. failed/canceled/succeeded;
3. подпись и проверку webhook;
4. сумму, валюту и snapshot предложения;
5. повторный webhook;
6. выдачу ровно один раз;
7. уведомление владельца через главный BotFlow;
8. обновление статистики;
9. смену активной кассы при существующем неоплаченном счёте.

Провайдер нельзя объявлять production-ready без реального sandbox/contract test.

## 10. E2E: подписка бота

1. Черновик доступен без оплаты только владельцу.
2. Публикация предлагает оплатить текущую конфигурацию.
3. Успешная оплата разрешает публикацию только соответствующего бота.
4. Неуспешное продление ставит этот бот на паузу, не затрагивая другие.
5. После оплаты бот возобновляется без потери сценария, лидов и медиа.
6. Gift Grant обнуляет только входящую в него конфигурацию.

## 11. Browser QA

Проверить в реальном Telegram WebView и desktop:

- light/dark;
- safe-area и системные кнопки Telegram;
- отсутствие горизонтального скролла;
- работу экранной клавиатуры;
- sticky CTA и bottom navigation;
- loading/empty/error/disabled/saved;
- длинные тексты и названия;
- закрытие приложения с реальными и без несохранённых изменений;
- отсутствие ошибок и отклонённых запросов в console/network.

## 12. Release gate

Релиз запрещён, если:

- есть необъяснённый 5xx в пользовательском сценарии;
- успешная оплата может не завершиться выдачей;
- повторный webhook создаёт дубль;
- readiness различается между frontend и backend;
- секрет возвращается клиенту или попадает в лог;
- Mini App не проходит проверку на реальном телефоне.
