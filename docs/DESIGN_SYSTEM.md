# BotFlow — Design System
Статус: актуальное визуальное направление. Реализация в коде должна мигрировать к нему постепенно, экран за экраном.

Дата фиксации: 26.08.2026.

## 1. Характер продукта

BotFlow должен ощущаться как зрелый рабочий SaaS для ежедневного использования:

- дружелюбный, но профессиональный;
- лёгкий, но не пустой;
- современный, но не «модный ради моды»;
- спокойный в рабочих областях;
- выразительный только в точках первого запуска, покупки и следующего действия.

Ориентиры: простота ManyChat, аккуратность Framer и доверие ЮKassa. Никакой интерфейс не копируется буквально.

## 2. Что считается AI-slop

Запрещено:

- фиолетово-синий градиент как фон большинства блоков;
- случайное свечение и blur без функциональной причины;
- одинаковая сетка из карточек для любого содержимого;
- огромные заголовки при малом количестве информации;
- декоративные иконки и эмодзи без смысла;
- бесконечные или демонстрационные анимации;
- стеклянные поверхности внутри обычных форм;
- несуществующие данные и маркетинговые обещания;
- повторение CTA на одном экране;
- скрытие сложного UX под красивой оболочкой.

## 3. Токены: три уровня

```text
Primitive → Semantic → Component
```

- Primitive хранит исходные значения цвета, пространства, радиуса и времени.
- Semantic описывает назначение: background, foreground, primary, danger.
- Component задаёт поведение конкретного элемента и всегда ссылается на semantic.

В React-компонентах запрещены случайные `hex`, размеры и тени. Исключения допускаются только для согласованных бренд-ассетов.

## 4. Цветовая система

### Light — тема по умолчанию

| Primitive | Значение | Назначение |
|---|---:|---|
| neutral-0 | `#FFFFFF` | raised surface |
| neutral-25 | `#FCFCFD` | фон приложения |
| neutral-50 | `#F7F8FA` | вторичные зоны |
| neutral-100 | `#EEF1F5` | muted/hover |
| neutral-200 | `#E1E5EA` | границы |
| neutral-400 | `#98A2B3` | tertiary text |
| neutral-600 | `#475467` | secondary text |
| neutral-900 | `#101828` | основной текст |

### Dark — нейтрально-чёрная, без синего оттенка

| Primitive | Значение | Назначение |
|---|---:|---|
| dark-950 | `#0B0C0F` | фон приложения |
| dark-900 | `#101216` | основные поверхности |
| dark-850 | `#15181D` | raised surface |
| dark-800 | `#1C2026` | hover/muted |
| dark-700 | `#292E37` | границы |
| dark-400 | `#9299A6` | secondary text |
| dark-100 | `#ECEFF4` | основной текст |

### Основной акцент

| Token | Light | Dark | Использование |
|---|---:|---:|---|
| primary | `#2563EB` | `#4D8DFF` | главный CTA, выбранное состояние |
| primary-hover | `#1D4ED8` | `#6BA1FF` | hover |
| primary-soft | `#EFF6FF` | `rgba(77,141,255,.14)` | спокойная выбранная зона |
| focus-ring | `#60A5FA` | `#6BA1FF` | focus-visible |

Синий не окрашивает весь экран. Он отвечает за действия, навигационный контекст и информационные состояния.

### Семантические цвета

| Смысл | Base | Soft | Пример |
|---|---:|---:|---|
| success | `#168A55` | `#ECFDF3` | бот работает, оплата прошла |
| warning | `#B76E00` | `#FFF7E6` | требуется настройка |
| danger | `#D92D20` | `#FEF3F2` | ошибка, удаление |
| info | `#2563EB` | `#EFF6FF` | подсказка |

Цвет никогда не является единственным носителем состояния: рядом всегда есть текст, иконка или форма.

## 5. Локальные цвета навигации

Разделы могут иметь собственный мягкий цвет активного состояния, но только локально в навигации:

- Обзор — blue;
- Сценарий — cyan;
- Продажи — green;
- Аудитория — orange;
- Аналитика — indigo;
- Настройки — neutral.

Неактивные пункты монохромны. При выборе появляется тонированная подложка, цвет иконки и короткий боковой маркер/мягкое локальное свечение. Контент экрана не перекрашивается вслед за пунктом меню.

## 6. Типографика

Основной шрифт: **Onest**. Он должен поставляться предсказуемо и иметь `system-ui` fallback. Plus Jakarta Sans не является каноническим шрифтом BotFlow.

| Token | Размер/строка | Weight | Назначение |
|---|---:|---:|---|
| display | `36/42` | 650–700 | один hero/KPI на экран |
| page-title | `28/34` | 650 | заголовок desktop |
| section-title | `20/28` | 600 | смысловой раздел |
| card-title | `16/24` | 600 | карточка/строка |
| body-lg | `16/24` | 400–500 | формы, мобильный текст |
| body | `15/22` | 400–500 | основной интерфейс |
| meta | `13/18` | 450–550 | даты, helper text |
| micro | `12/16` | 550–600 | badge/overline |

Денежные значения, даты и KPI используют tabular numerals. На мобильном поля ввода не меньше 16px, чтобы iOS не увеличивал страницу.

## 7. Пространство и геометрия

- базовый ритм: 4px;
- рабочая шкала: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64`;
- отступ страницы: 16px mobile, 24–32px desktop;
- controls: радиус 12px;
- cards: 16px;
- modal/sheet: 20–24px;
- promo/Welcome surface: 24–32px;
- touch target: минимум 44×44px.

Карточка используется только когда объединяет одну сущность или действие. Простое содержание разделяется пространством и линиями, а не вкладывается в бесконечные карточки.

## 8. Тени, градиенты и blur

- рабочие поверхности используют границу и различие фона;
- тень нужна для плавающих слоёв и явно приподнятого объекта;
- мягкий градиент разрешён в Welcome, Upgrade и редкой PromoCard;
- градиент не должен быть основным содержимым или мешать контрасту;
- blur разрешён для backdrop модального слоя и sticky-панели над прокручиваемым контентом;
- glow не должен выходить из своего контейнера или перекрывать соседние блоки.

## 9. Основные компоненты

### Button

Варианты: primary, secondary, outline, ghost, destructive, link.

Высоты: 36px compact, 44px default, 52px large. Primary CTA на экране обычно один.

Обязательные состояния: default, hover, active, focus-visible, disabled, loading. В loading ширина кнопки не меняется.

### Input и Textarea

- label расположен над полем;
- helper/error — под полем;
- default height 44–48px;
- textarea для сообщений имеет достаточную высоту и растёт до разумного предела;
- rich text toolbar находится рядом с текстом и не требует лишнего открытия;
- счётчик символов показывает приближение к лимиту до ошибки;
- секреты показываются безопасной маской, но пользователь понимает, что значение сохранено.

### Card и List Row

- Card — одна смысловая сущность;
- List Row — повторяющийся набор объектов: боты, лиды, платежи, кассы;
- интерактивная строка кликабельна целиком;
- действие строки не перекрывает текст на мобильном;
- длинные значения переносятся либо сокращаются предсказуемо.

### Dialog и Sheet

- desktop: modal/dialog по сложности;
- mobile: bottom sheet для короткого выбора, fullscreen sheet для длинной формы;
- заголовок и закрытие остаются видны;
- контент прокручивается независимо;
- sticky footer не перекрывает последнее поле;
- подтверждение закрытия появляется только при реальных несохранённых изменениях.

### Feedback

- Toast не перекрывает Telegram header и учитывает safe-area;
- короткое сообщение занимает одну строку, длинное — до двух;
- критичная полноэкранная ошибка имеет один понятный CTA;
- loading, empty, error и stale-data не смешиваются;
- ошибка говорит, что произошло и что делать дальше.

### Media attachment

Один и тот же компонент используется в старте, дожимах, сообщении выбора и предложениях:

- пустое состояние — компактная кнопка «Добавить фото или видео»;
- загрузка — progress и возможность отмены;
- загружено — превью, тип файла, «Заменить» и «Удалить»;
- фраза «Синхронизировано с Telegram» пользователю не показывается;
- preview остаётся удобным на мобильном;
- лимиты видны до выбора файла.

## 10. Навигация

Desktop использует сгруппированный sidebar и Bot Context Switcher. Mobile показывает не более 4–5 главных направлений и не дублирует системные кнопки Telegram.

Активный маркер перемещается с анимацией 180–220ms. При `prefers-reduced-motion` движение заменяется мгновенной сменой цвета.

## 11. Motion

Анимация отвечает только за причинно-следственную связь:

- hover/press: 120–160ms;
- смена навигационного состояния: 180–220ms;
- открытие sheet/modal: 200–260ms;
- появление сохранённого состояния: 160–200ms;
- layout-переход раскрытия блока: до 240ms.

Запрещены постоянное плавание, бесконечный shimmer после загрузки, вращение декора и анимация каждого текста при входе.

## 12. Responsive и длительная работа

- горизонтального скролла страницы быть не должно;
- клавиатура не перекрывает активное поле и sticky CTA;
- нижняя навигация может скрываться при вводе текста, освобождая рабочую область;
- рабочие формы должны быть удобны 30–60 минут;
- редактор сценария сохраняет понятную последовательность и позицию пользователя;
- desktop использует ширину экрана, но ограничивает длину строк текста;
- таблицы на мобильном превращаются в содержательные строки, а не сжимаются.

## 13. Контент и реальные изображения

Фотография или иллюстрация добавляется только в заранее определённый слот:

- Welcome/первый запуск;
- preview шаблона сценария;
- PromoCard покупки или расширения;
- Empty State, где изображение объясняет результат;
- пользовательское медиа в редакторе.

Тема изображения согласуется до генерации. Декоративная картинка не используется для заполнения пустоты.

## 14. Проверка каждого экрана

Перед завершением экран проверяется по вопросам:

1. Главная задача понятна за 3–5 секунд?
2. Есть один очевидный следующий шаг?
3. Loading, empty, error, disabled и saved честны?
4. Удобно ли на Telegram mobile и desktop?
5. Нет горизонтального скролла и перекрытий?
6. Не утомляет ли экран при работе 30–60 минут?
7. Каждый цвет, эффект, текст и иконка имеют функциональную причину?
